# Sprint 006 — Client Bot (S2-D)

## Goal
Запустить платформенный клиентский бот. Клиент переходит по ссылке
мастера, открывает Mini App, бронирует запись — мастер получает
уведомление в свой owner-бот. client_tg_id сохраняется в aria_bookings,
что разблокирует S1-B (напоминания клиентам).

## Business Objectives
- Клиент может записаться самостоятельно без участия мастера
- Мастер получает мгновенное уведомление о новой записи
- client_tg_id сохраняется → напоминания клиентам становятся возможными

## Users Affected
- Конечный клиент салона (новый пользователь системы)
- Владелец салона (получает уведомления, делится ссылкой)

## Inputs
- CLIENT_BOT_TOKEN — новый env var (токен создаётся в BotFather)
- tenant_id — передаётся через deep link ?start=tenant_{id}
- MINIAPP_URL — уже есть в config.py
- _tg_notify() — уже есть в server.py, использовать для уведомлений
- aria_bookings — существующая таблица, добавить client_tg_id если нет

## Outputs
- aria/handlers/client_bot.py — новый файл с хендлерами клиентского бота
- aria/main.py — регистрация второго polling бота
- server.py — при POST /api/bookings сохранять client_tg_id
  и уведомлять owner-бота мастера
- .env.example — добавить CLIENT_BOT_TOKEN с комментарием

## Out of Scope
- Не добавлять мульти-мастер логику (это S3)
- Не менять Mini App экраны
- Не писать тесты в этом спринте
- Не трогать APScheduler напоминания (разблокируются автоматически)
