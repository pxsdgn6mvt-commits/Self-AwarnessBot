# Sprint 003 — Reliability: Email Jobs + Admin Notifications

## Goal
Устранить два реальных риска надёжности: потерю email-джобов при рестарте
Railway и молчаливые падения в scheduler-джобах без уведомления платформ-админа.

## Business Objectives
- Email-мониторинг тенантов не прерывается после рестарта Railway
- Платформ-админ получает Telegram-уведомление при критических ошибках
- Владельцы салонов не теряют функциональность незаметно

## Users Affected
- Платформ-админ (получает уведомления)
- Владельцы салонов (их email-джобы выживают после рестарта)

## Inputs
- ADMIN_TELEGRAM_ID — переменная окружения (уточнить есть ли в .env.example)
- Существующий `_watch_tenants` в main.py — точка восстановления джобов
- Существующий `start_email_job` — функция регистрации email-джоба
- `_run_reminder_scan` — критический джоб, падения которого надо репортить

## Outputs
- Email-джобы регистрируются повторно при каждом вызове `_watch_tenants`
  (или при старте, если тенант уже активен)
- При падении `_run_reminder_scan` или `api_create_booking` — платформ-админ
  получает сообщение в Telegram с описанием ошибки
- Scheduler-джобы в menu.py логируют ошибки вместо `pass`

## Out of Scope
- Не создавать отдельный модуль notify_admin.py (это Sprint 004)
- Не трогать Mini App, DateScreen, WebApp-кнопку
- Не менять схему БД
- Не писать тесты
